# Advanced DSP Engine

## Architecture

The advanced DSP engine extends the Milestone 1 DSP package without changing API or frontend assumptions. Coding, equalization, and synchronization are isolated in framework-free modules:

- `wavecore.dsp.advanced_coding`
- `wavecore.dsp.equalization`
- `wavecore.dsp.synchronization`

This keeps each algorithm independently testable and lets the simulation engine adopt them stage by stage.

## Mathematics

Convolutional coding uses a rate-1/2, constraint-length-7 encoder with octal generators `(133, 171)`. Viterbi decoding uses maximum-likelihood sequence estimation with Hamming branch metrics for hard-decision inputs

Reed-Solomon coding is implemented as a systematic narrow-sense RS code over GF(256) using primitive polynomial `0x11D`. Encoding divides by the generator polynomial. Decoding computes syndromes and solves exact error magnitudes for candidate locations within the correction radius.

LDPC support uses a binary parity-check matrix and min-sum belief propagation over Tanner graph messages. Systematic encoding is available for matrices of the form `H = [P | I]`.

Polar coding uses Arikan's polar transform and successive-cancellation decoding from LLRs. The reliability set can be generated by polarization weight ordering.

MMSE equalization applies:

```text
X_hat = Y * H* / (|H|^2 + N0)
```

Frequency correction applies a complex exponential derotation. Timing synchronization uses matched-filter correlation against a known preamble.

## Industrial Usage

These blocks map directly to modem engineering tasks: FEC selection, carrier and timing recovery, pilot-aided channel estimation, and robust equalization. Qualcomm-class systems use more specialized versions of the same principles, including LDPC and Polar codes in 5G NR.

## API Specification

Milestone 2 exposes these algorithms as backend capabilities while preserving the existing `POST /api/v1/simulations/run` contract. Future frontend integration should bind coding/equalizer selectors to request parameters rather than hard-coded UI behavior.

```http
GET /api/v1/capabilities
```

Returns supported modulation schemes, channel models, coding schemes, equalizers, and visualization families.

```json
{
  "message": "WaveCore X",
  "modulation": "QPSK",
  "coding": "HAMMING74",
  "equalizer": "MMSE",
  "channel": {"model": "AWGN", "snr_db": 30}
}
```
